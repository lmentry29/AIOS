## F-020 — gVisor provenance artifacts were unsigned

**Status:** fixed (offline trust chain); production key provisioning and CI identity
attestation remain open.

The runtime pin and rootfs manifest were integrity-checked but not authenticated: anyone who
could replace both artifact and expected digest could authorize execution. Both kinds now
carry detached Ed25519 statements verified against the checked-in trust root before use, and
the provider requires the signed rootfs manifest digest to equal the measured rootfs that is
copied and executed. Rejection tests cover missing/malformed/wrong-key/revoked/expired/
replayed/modified artifacts. No Sigstore/SLSA level is claimed; see
`docs/security/artifact-signing.md`. The repository trust root is intentionally empty until an
operator provisions a key, so default gVisor verification fails closed.
