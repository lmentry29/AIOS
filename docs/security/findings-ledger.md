| F-001 | High | Timeout or cancellation killed only the direct child, so a sandbox supervisor's descendants could survive and keep running. | **Fixed** | Process group kill + real-process tests (`process.test.ts`, commit `dec854a`). |
| F-002 | High | The verifier accepted an `execution_result` without recomputing the executor's evidence digest against the durable execution record, so a forged result could be verified if it reached the port. | **Fixed** | The verifier now requires a completed durable attempt, the same executor principal, and a matching `result_sha256`; acceptance evidence records the execution ID, attempt, and bound digest. | F-003 | Medium | bubblewrap has no cgroup CPU/memory controls; a memory bomb can stress the host. | **Fixed (per-process bubblewrap RLIMIT; cgroup/Docker unverified)** | Every bubblewrap run is prefixed inside the namespace with trusted `/usr/bin/prlimit --as=1342177280 --cpu=ceil(timeout_ms/1000) --nproc=128`; the fixed wrapper requires the exact `Max address space`, `Max cpu time`, and `Max processes` values in `/proc/self/limits` plus `Seccomp: 2` before exec. Missing proof raises `SandboxResourceLimitUnavailableError`, journals `sandbox_resource_limit_unavailable`, and the verifier rejects both that failed attempt and its own missing proof. Success evidence records the limits. Regressions: 2 executor/verifier denial tests plus 3 live bwrap limit tests; full live suite 17/17. Drill (`tools/security/resource-limit-drill.mjs`): legitimate Perl exit 0; memory bomb exit 1, `Out of memory!`, `timed_out:false`; filter still `Seccomp: 2`. **Residual:** per-process limits, not aggregate cgroup accounting; up to 128 descendants can each reserve 1.25 GiB; RLIMIT_AS is virtual address space, not RSS; Node/libuv startup is killed by the F-007 io_uring KILL; Docker/gVisor/Seatbelt/Apple Containerization unverified. |
| F-004 | Medium | No per-workspace disk quota; a workload can fill the filesystem before the timeout. | **Fixed (live sampling; not a hard quota)** | `LocalCommandExecutor` and `LocalCommandVerifier` sample the real per-task workspace every 25 ms while the provider is live, abort the sandbox on the configured `execution.workspace_max_bytes` ceiling (default 256 MiB, bounds 1 KiB–8 GiB), discard the oversized workspace, and the managed lifecycle journals `disk_quota_exceeded`; the verifier binds rejection to that failed attempt and its evidence digest. `--size 67108864` bounds the sandbox `/tmp`. Regressions: 5 quota tests plus 2 live bwrap drills. Real drill: over-cap run stopped/discarded with 0 matching processes; under-cap and sequential runs completed at 65,536 and 32,768 bytes (ADR-0026). **Residual:** a fast writer can overshoot between 25 ms samples, symlinks are skipped, hardlinks are counted per name, and writes outside `/workspace` are not attributed to the run; no unprivileged hard block quota exists here. Docker remains unverified. |
| F-005 | Medium | `sandbox-exec` is deprecated on macOS and has no published CLI replacement; the Seatbelt adapter may stop working on a future macOS. | **Accepted, unverified; fail-closed regression** | `SeatbeltSandbox.check()` rejects every non-macOS host, and the host composes only a provider whose probe passes; `apps/host/tests/execution.test.ts` now proves the unavailable path instead of a bare-process fallback. **Blocker:** no macOS 26/Apple silicon host and no `sandbox-exec` on this Linux host, so real profile enforcement is unverified. **Unblock:** run the live Seatbelt probe on current macOS, then implement and validate Apple Containerization on macOS 26/Apple silicon; keep both unverified until that evidence exists. |
| F-006 | Medium | Docker provider was never executed against a daemon in this environment; only argument construction is tested. | Unverified | Run the adapter on a host with rootless Docker and cgroup v2; record in the validation ledger. |
| F-007 | Medium | No seccomp filter inside the bubblewrap namespace; the workload can call any syscall the kernel permits. | **Fixed (bubblewrap seccomp deny-list; Landlock/Docker unverified)** | Every bubblewrap invocation installs a generated classic-BPF filter with an architecture guard and `KILL_PROCESS` for ptrace, mount, namespace, keyring, module, bpf, perf, io_uring, userfaultfd, and related syscalls. A fixed wrapper proves the kernel reports `Seccomp: 2` before exec; missing proof is `sandbox_filter_unavailable`, and a denied syscall (`SIGSYS`, bwrap status 159) is `sandbox_syscall_denied`. Both are journaled and verifier-bound. Live drill: profile `aios-seccomp-deny-v1-x64`, SHA-256 `12e5ae012d8d9bee997b0530b92e9f8b8271b0c2cf5fca2290e655f7921fbaac`, denied run stopped with 0 workspace entries/0 processes, legitimate and subsequent runs exit 0. **Residual:** this is a deny-list, not a complete allow-list; unlisted syscall families remain callable. Landlock is absent from the active LSM list; Docker/Seatbelt/gVisor/Apple Containerization remain unverified; no aggregate cgroup CPU/memory accounting or hard disk quota. Node/libuv probes `io_uring_setup` at startup and is killed with SIGSYS by this deny-list; use a workload that does not probe io_uring or amend the filter policy deliberately. |
| F-008 | Medium | Journal compaction and a tested backup/restore path were absent; the journal failed closed at its size limit and a damaged journal had no recovery route. | **Fixed** | Checkpoint compaction plus digest-verified, idempotent offline restore (ADR-0025); size-limit, corruption-recovery, tampered-archive, idempotency, and verifier-after-compaction regressions pass, and `tools/security/journal-drill.mjs` executed all seven drill steps. |
| F-009 | Medium | Policy artifacts are unsigned; there is no detached signature, key rotation, or external audit custody. | **Accepted (mitigated; unsigned)** | Every new policy lifecycle event records a canonical SHA-256 of the exact policy; `FilePolicyRegistry` recomputes it on load and rejects substituted policy content even when the event hash chain still verifies (`file-policy-registry.test.ts`, code head `24d2791`). **Blocker:** no KMS/HSM/Sigstore key custody or signing material is available in this environment. **Unblock:** provision an external signing key with documented rotation and audit custody, add detached-signature verification and rotation drills, and verify compromise/recovery; until then this is tamper evidence, not cryptographic provenance. |
