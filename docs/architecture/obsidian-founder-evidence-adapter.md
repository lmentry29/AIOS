# Obsidian Founder Evidence Adapter

## Decision boundary

ADR-0014 is Accepted: the Obsidian vault is the persistence substrate for Founder Intelligence; AIOS validates canonical records; no separate database is introduced for Founder Intelligence.

This adapter is deliberately **read-only**. It exposes existing notes as source evidence. It does not convert unmarked Markdown into KnowledgeRecord or ArtifactEntity objects, create permanent Memory, modify frontmatter, rename files, or write to the vault.

The prior read-only reconciliation found no notes explicitly managed as Founder canonical objects. Therefore, the adapter performs no hydration or migration. Any future classifications remain proposals for human review.

## API contract

The adapter expects the authenticated local Obsidian++ API:

- GET /api/vault/evidence — metadata inventory, including the 11 AI Memory folder, source paths, frontmatter, modification timestamps, SHA-256 content hashes, byte counts, and warnings. The endpoint does not return note bodies.
- GET /api/vault/file?path=... — retrieves one note body after path validation.

The adapter never calls POST /api/vault/append or POST /api/vault/complete.

The Obsidian++ server must be running on loopback and must have the local authentication and path-containment hardening described in the Obsidian++ security branch. The adapter rejects non-loopback URLs, redirects, short passwords, unsafe paths, malformed metadata, duplicate paths, oversized inventories, and content that no longer matches the metadata hash.

## Authorization model

The entire vault is represented by one explicit collection resource UUID, supplied by the trusted host as vaultResourceId. Before listing metadata or reading any note body, AuthorizedVaultEvidenceReader asks the shared FounderAuthorizationPort for:

- actor_id: the authenticated principal supplied by the trusted host
- action: read_evidence
- resource_id: vaultResourceId

If authorization is absent, false, or throws, the operation fails closed and makes no HTTP request.

This is a collection-level grant: a policy that permits read_evidence on vaultResourceId grants access to all notes returned by the evidence inventory. Do not create that policy implicitly. A trusted host must explicitly attach a resource policy and decide which human or agent principals may read the collection. Per-note policies are not yet implemented.

Each note receives a deterministic UUIDv5 source_id derived from vaultResourceId and its normalized relative path. Renaming or moving a note changes its source_id and requires the host's resource-policy mapping to be reviewed.

## Construction

The host creates the reader with a local-only base URL, the password generated by Obsidian++, the stable vault resource UUID, and the same authorization service used by Founder and Orchestration:

```ts
const vaultEvidence = new AuthorizedVaultEvidenceReader(
  {
    baseUrl: 'http://127.0.0.1:4444',
    password: process.env.OBSIDIAN_LOCAL_PASSWORD!,
    vaultResourceId: process.env.OBSIDIAN_VAULT_RESOURCE_ID!,
  },
  authorizationService,
);

const founder = new FounderInterface(
  canonicalEntities,
  learningRecords,
  authorizationService,
  { decisionCollectionId },
  undefined,
  vaultEvidence,
);

const result = await founder.queryEvidence(
  'what did I decide about the Founder Intelligence persistence model',
  'human:founder',
);
```

The host must validate required environment variables at startup and must not log or commit the local password. Do not use non-null assertions in a production composition root; validate configuration and fail startup if values are missing.

## Snapshot integrity and limits

- Default and only accepted API origin: http://127.0.0.1:4444. The adapter rejects localhost, IPv6 loopback, LAN, and remote hosts.
- Basic Authentication is sent only to the configured loopback origin.
- Redirects are rejected and responses are not cached.
- Request timeout: 10 seconds.
- Maximum inventory: 500 notes.
- Maximum note size: 1 MiB.
- Maximum total inventory size: 20 MiB.
- Fetch concurrency: 4.
- The adapter checks the content byte count and SHA-256 hash against the inventory snapshot before returning a note.
- Returned records and nested metadata are frozen to prevent accidental mutation.

## Query behavior

FounderInterface.queryEvidence performs deterministic all-term lexical matching over path, title, folder, frontmatter, and note body. It returns matching source records, inventory warnings, the inventory timestamp, and the total file count. It does not synthesize or promote memories. Semantic retrieval, embeddings, summarization, contradiction resolution, and classification approval are not implemented by this adapter.

## Verification status

The adapter is covered by mocked HTTP tests for loopback URL validation, Basic Authentication, redirect rejection, authorization-before-read, path traversal rejection, duplicate paths, content-hash mismatch, and FounderInterface query behavior.

No live vault has been read or modified by CI. Production integration remains blocked until the Obsidian++ security PR is merged, the user starts the local server, a trusted host configures the vault resource policy, and a controlled local smoke test is completed.
